1. Project Overview

The ERP Predictive Workforce Optimization system is an artificial-intelligence-based prototype designed to support Human Resources and operational workforce planning.

The application combines:

Machine Learning for predicting required labor hours.
Operations Research for employee-task assignment.
Cost analysis for comparing optimized and manual scheduling.
Workforce analytics for utilization analysis.
Interactive ERP planning through Streamlit.

The system follows:

ERP Work Orders → Data Preparation → ML Forecast → Predicted Labor Hours → Optimization → Workforce Allocation → Cost & HR Analysis

The main purpose is to combine workload prediction with workforce decision-making.

2. Project Objectives

The system is designed to answer:

How much workforce capacity will incoming work require?

and:

Which employees should perform that work?

Main objectives include:

Forecast labor hours.
Compare XGBoost and Random Forest.
Evaluate MAE, RMSE and R².
Provide an interactive ERP interface.
Match employees according to skills and capacity.
Consider overtime, preferences and task priority.
Minimize workforce cost.
Compare AI optimization with a manual baseline.
Calculate utilization and generate HR recommendations.
Provide a downloadable Google Colab notebook.

5.2 Input Features

Complexity — Task complexity from 1–5.
Est. Deliverables — Expected deliverables.
Required Skill — Required skill level.
Priority — Priority from 1–3.
Productivity Index — Relative productivity.
Shift Efficiency — Working-shift efficiency.

5.3 Target Variable

The target variable is:

actual_hours

It represents required labor hours.

The synthetic value is generated from complexity, deliverables, skill, priority, productivity, shift efficiency and random noise.

Therefore, the project demonstrates the ML methodology using simulated rather than historical ERP data.

6. Machine Learning Models

6.1 XGBoost

Model:

Configuration:

max_depth = 5
learning_rate = 0.04
subsample = 0.9
colsample_bytree = 0.9

XGBoost is suitable for structured business data and nonlinear relationships.

6.2 Random Forest

Model:

Configuration:

n_estimators = 160
max_depth = 8
random_state = 42
n_jobs = -1

Random Forest provides an alternative ensemble regression model.

7. Data Encoding

Department is converted using:

pd.get_dummies()

Prediction features are reindexed to match the training columns, ensuring compatibility when new ERP records contain different department combinations.

8. Model Evaluation

The application calculates:

MAE — Mean Absolute Error
Measures average prediction error in hours. Lower is better.

RMSE — Root Mean Squared Error
Penalizes larger prediction errors. Lower is better.

R² — Coefficient of Determination
Measures explained variance. Higher is better.

The project target is:

R² ≥ 0.85

Because the dataset is synthetic, the actual measured result must be reported after running the application.

9. Feature Importance

The eight most important features are visualized to provide basic model interpretability.

13. Workforce Optimization

The optimization engine uses:

Google OR-Tools + SCIP

The problem is formulated as Mixed Integer Programming.

14. Decision Variables

For each task and employee:

x(i,j) = 1 if employee j performs task i.
x(i,j) = 0 otherwise.

Overtime is represented using continuous employee variables.

15. Optimization Constraints

Every task must be assigned exactly one employee.

Employees must meet the required skill level.

Assigned workload cannot exceed regular plus overtime capacity.

Overtime represents workload exceeding regular capacity.

16. Optimization Objective

The optimizer minimizes workforce cost while considering:

Predicted task hours.
Employee hourly rates.
Preferences.
Task priority.
Overtime cost.

The objective balances:

Low cost + suitable assignment + priority + preferences + capacity.

17. Employee Preferences

Employees can specify preferred task IDs, for example:

102,103

A configurable preference bonus allows these preferences to influence optimization.

18. Task Priority

Priority levels are:

1 — Highest
2 — Medium
3 — Lower

Higher-priority tasks receive stronger optimization incentives.

19. Overtime Configuration

The default overtime multiplier is:

1.5×

For example:

$40 × 1.5 = $60/hour

The multiplier can be changed through the Streamlit sidebar.

20. Manual Baseline

The manual baseline uses a simpler strategy:

Identify eligible employees.
Select the cheapest available employee.
Consider capacity.
Use overtime if required.
Calculate total cost.

Unlike the optimizer, the baseline does not globally optimize all assignments.

21. Cost Analysis

The application calculates:

Manual baseline cost.
AI optimized cost.
Estimated savings.
Savings percentage.

Formula:

Savings = Manual Baseline − AI Optimized Cost

Savings % = Savings / Manual Baseline × 100

Because the data is synthetic, savings are illustrative and should not be treated as guaranteed real-world financial results.

22. Workforce Utilization

Utilization is calculated as:

Utilization = Total Assigned Hours / Total Available Capacity × 100

Capacity includes:

Regular Hours + Overtime Capacity

Approximate categories:

90% or above — Highly utilized.
35% or below — Potentially underutilized.
Between these levels — Generally balanced.

23. HR Recommendations

The system automatically generates recommendations.

Highly utilized employees may require:

Task reallocation.
Additional workforce capacity.
Reduced future workload.

Low-utilization employees may be candidates for:

Additional compatible work.
Reallocation from overloaded employees.

Balanced employees require no immediate reallocation.

29. Why a GPU Is Not Required

The project uses small-scale tabular data rather than deep learning.

The dataset contains only 1,800 samples and the models use 160 trees.

Therefore, CPU-based training and inference are sufficient.

The OR-Tools optimization problem is also small enough for CPU execution.

30. Performance and Caching

36. Important Technical Limitations

The prototype uses synthetic training data and a synthetic target variable.

Therefore:

Model performance may be easier to achieve than with real ERP data.
Results do not represent real organizational behavior.
Employee availability, vacation, shifts, location and certifications are not fully modeled.
Tasks are assigned to one employee rather than divided.
Detailed calendar scheduling is not implemented.
Savings are simulated rather than guaranteed.
